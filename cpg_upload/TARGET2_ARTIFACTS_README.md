# JUMP-Lite Target-2 publication artifacts

This package contains the frozen segmentation masks, per-site object-level
measurements, and compact raw-feature profiles used for the four-plate
**Target-2 compression subanalysis** in the JUMP-Lite paper. It is a
publication-specific artifact package, not an extension of the 655,101-site
JUMP-Lite v1.0 image/embedding cohort.

## Scope

Target-2 contains 1,536 wells and up to six image sites per well across four
plates from `source_3`, `source_4`, `source_5`, and `source_6` (9,216 expected
sites). The package retains the actual recovered coverage of each artifact; it
does not silently intersect codecs or synthesize missing outputs.

## Segmentation masks

The package contains 163,786 compressed NumPy NPZ files totaling
4,303,626,240 bytes. Each site has a paired cell and nuclei mask. Each NPZ has
one array named `arr_0` with dtype `uint16`. Spatial dimensions follow the
source images: `1080 × 1080` for `source_3` and `source_4`, `998 × 998` for
`source_5`, and `970 × 970` for `source_6`. Historical pipeline runs stored
some arrays as `(height, width)` and others as `(1, height, width)`; the
manifest records the exact dimensionality, and paired cell/nuclei masks always
have identical shapes. Array value `0` denotes background; positive integer
values are instance labels local to the image and object type. Label values
must not be compared across sites, codecs, or between cell and nuclei arrays.

The masks were generated by the recorded Aliby/Nahual Cellpose pipeline from
each codec's pixels. `manifests/provenance.json` inventories and hashes all
recorded pipeline scripts found with the outputs.

## Compact profiles

The package includes 66 canonical compact Parquet artifacts totaling
506,590,967 bytes:

- 9 aggregated `cp_measure` raw-feature profiles;
- 7 cell-count tables; and
- 50 deep-learning raw-feature profiles covering DINOv2, randomly initialized
  DINOv2, MorphEm, OpenPhenom, and the clipped-input SubCell variant.

These compact, well-level Parquets are the canonical raw-feature inputs used by
the paper analyses. They replace neither the original images nor the per-site
object-level measurements published alongside them. The manifest freezes each
Arrow schema by digest. The public provenance records a release-time snapshot
of the producer source and dependency lockfiles; the original extraction
runtime environment was not embedded in the compact Parquets and is not
claimed to be fully reconstructed.

Most compact profiles contain all 1,536 Target-2 wells. The
`cp_measure/jpegxl_lossy_d15` profile contains 1,490 wells and is marked
`partial` in `manifests/profiles.parquet`. File-level row counts, column counts,
byte sizes, SHA-256 hashes, codecs, models, and public object keys are recorded
in that manifest.

## Per-site object features

The package also preserves 86,989 per-site `cp_measure` Parquets totaling
253,990,072,630 bytes. These are long-form object-level measurements, not
well-level profile matrices. They contain `tile`, local segmentation `label`,
feature `branch`, feature `metric`, numeric `value`, object type, and `tp`.
Together they contain 41,487,496,575 rows. Object labels are local to a file and
object type; they are not globally stable identifiers and must not be joined
across sites or codecs.

Profile and retained-mask availability are deliberately represented
independently. In particular, 5,218 D2-E8 object-feature files outlive the
currently retained D2-E8 mask outputs and remain valid source artifacts. The
manifest records mask-pair availability for every file and never intersects
the two inventories silently.

Seventy valid Parquets are empty because no measured objects survived for
those sites. Empty files use `tp: int64`; nonempty files use `tp: uint8`, and
the manifest records the corresponding Arrow schema digest and zero row count.
Every nonempty file has a row count divisible by 1,275.

## Integrity and provenance

`manifests/masks.parquet` has one row per published mask object and records its
site identity, object type, codec, coverage status, byte size, SHA-256 digest,
exact dimensionality and spatial shape, and package-relative object key.

`manifests/object_features.parquet` has one row per per-site object-feature
file and records its site identity, codec, coverage and retained-mask status,
shape, empty status, byte size, SHA-256 digest, Arrow schema digest, and
package-relative object key.

`manifests/profiles.parquet` has one row per compact profile and records its
family, model, codec, coverage status, shape, byte size, SHA-256 digest,
well-identity-set digest, and package-relative object key.

`manifests/provenance.json` binds all three manifest hashes, the README hash,
the builder hash, source inventory totals, exact site-set and schema digests,
the relationship between object features and retained masks, the recorded
mask-pipeline scripts, and
a release-time hash inventory of compact-profile producer code and dependency
lockfiles. The upload workflow validates all local hashes, uploads data before
package metadata, and verifies the exact staging keys, sizes, and stored
SHA-256 checksums before marking the package complete.
